# 白纸单词 · 变更日志

本文件记录「白纸单词」项目的版本演进。当前版本：**v1.5.0**。

v1.4.0 由两条**并行开发线**合并而成，两条线都在 v1.1.0 基线上各自演进：

| 开发线 | 版本 | 内容 |
|---|---|---|
| 单词本线（本机） | v1.2.0 → v1.3.0 | 内置词库、一键导入成白纸、分组面板 |
| 协作者线 | v1.2.1 | 记忆模式自动朗读、6 层刀气 |

融合结果 **v1.4.0 ⊇ v1.2.1 ∪ v1.3.0**：协作者的朗读与刀气、本机线的单词本，两者功能全部保留、互不覆盖。

## v1.5.0（2026-09-12）· 五处体验问题修复

一次使用反馈清单的集中修复，按用户提出的顺序逐条对应：

### 1. 夜间模式滚动条与深色背景冲突
- **问题**：夜间模式下页面/面板滚动条仍是系统默认的浅色，在深底上亮出一条白杠。
- **修复**：新增主题变量 `--scroll-thumb` / `--scroll-thumb-hover`（日间暖灰、夜间浅米），
  并补齐全套滚动条样式 —— Firefox / 新版 Chromium 认 `scrollbar-color`，
  WebKit 内核（Chrome / Edge / Electron 桌面版 / Safari）认 `::-webkit-scrollbar-*`，两套都写才全覆盖。
- **覆盖范围**：`html`、首页滚动区、`.panel-body`（统计 / 单词本）、`.shelf-list` 横向滚动条。

### 2. 导出改为「单词|释义」的 txt
- **问题**：导出的是 `.json`，用户要的是能直接看/改的文本。
- **修复**：导出改为 **UTF-8 带 BOM 的 `.txt`，每行一条「单词|释义」**（与内置词库 `wordbooks.js` 同格式），
  Windows 记事本、Excel 都能直接打开不乱码。
- **导入**：`#import-file` 放开 `.txt`；解析器 `parseImportText()` 同时兼容
  · 新 txt：分隔符支持 `|` `｜` 与制表符，跳过空行与 `#` 注释，无分隔符时按「只有单词、释义为空」处理
  · 旧 `.json` 备份：原样保留 `x / y / recallCount` 等字段（向下兼容）
- 导入仍为**追加到当前白纸**，坐标用 `gridSpot()` 递补网格位，连续导入不会叠在一点。

### 3. 新增删除按钮
- **统计面板**：每行末尾一个删除键（`removeWord()`），删掉录错的单词不必整张白纸重来；
  删除后同步刷新统计列表、工具栏计数、屏上单词卡。
- **记忆模式单词卡**：卡片左上角新增删除键，与右上角「重听」左右对称，当场发现写错即可删。
- 两个入口共用 `removeWord(id)`：确认框二次确认 → 原地 `splice` → 落盘 → 清屏上残留。

### 4. 游戏模式：释义框贴边变形
- **问题**：单词抛到屏幕边缘被切开时，弹出的释义框会变形、文字被挤成多行。
- **根因**：绝对定位盒子的**可用宽度 = 容器宽 − left**。单词在右缘时 `left` 已接近视口宽，
  可用宽度只剩几十像素，收缩式布局把盒子压成窄条，`max-width` 拦不住（它只封顶、不兜底）。
- **修复**：`.def-pop` 改 `width: max-content`（宽度只由内容与 `max-width` 决定），
  `showDefinition()` 测量真实尺寸后把中心点收进可视区（左右上下各留 10px），保证整框可见。
- **回归测试**：新增用例用固定随机源把单词逼到 x≈1130 / 视口 1200，断言释义框不越界；
  该用例在旧实现上实测失败（left=1272）。

### 5. 移动端排版
- **问题**：手机上工具栏按钮挤成一团（gap 4px、padding 5px 9px、高度约 26px），点不准也看不清。
- **修复**：新增 `@media (max-width: 600px)`（原 480px 断点上调），规则要点：
  · 工具栏拆两行：第一行「标题 + 纸名」，第二行整块操作区
  · 操作区改 4 列等宽网格（`repeat(4, minmax(0,1fr))`）：模式切换独占一行三等分，
    其余「统计/导出/导入/清除/主题/音效/朗读 + 单词计数」正好填满两行，不留空行
  · 触摸目标统一 ≥ 44px，间距 8px；首页按钮、单词卡按钮、面板关闭键、
    词库导入键、统计行删除键一并放大
  · **游戏进行中**（`body.game-mode`）收起标题行与次要按钮，工具栏只剩模式切换，
    游戏 HUD 顺势下移到 80px、连击环到 160px，把整屏让给游戏
  · 底部提示折行时居中；白纸卡加宽到 160px，名字不再被图标挤成省略号

### 测试
- 新增 `tests/word-io.test.js`（12 条）：导出 txt 格式与 BOM、导入 txt / 旧 json / 容错 / 空文件、
  统计面板删除、取消删除、单词卡删除、释义框贴边不越界、空释义不弹框。
- 全量 **51 条全绿**（game-mode 31 + wordbook 8 + word-io 12）。

## v1.4.2（2026-09-11）· 朗读开关误发声修复

- **问题（Bug）**：点击工具栏「朗读」开关时，会**凭空冒出一句单词读音**，且与界面无关 ——
  在录入/游戏模式下也会响，用户完全不知道声音从哪来。
- **根因**：开关的点击回调里除了切开关，还「顺手」读了**一个随机单词**做音效演示：

  ```js
  if (speakOn) { unlockSpeech(); var w = pickWord(); if (w) speakWord(w.word, currentWordEl); }
  ```

  `pickWord()` 从整张白纸随机取词，与当前模式、屏幕上是否有卡片都无关，于是变成「开关一开就乱叫」。
  该写法来自协作者线 v1.2.1 的「让用户立刻听到效果」，但交互上属于惊吓式反馈。
- **修复**：开关只做两件事 —— ① 切开关状态并持久化；② 在当前用户手势里**静默解锁**语音权限
  （`unlockSpeech()`：`volume = 0` 的空 utterance，出声即被 `cancel()`，本身不发声）。
  **不再朗读任何单词**。想试听随时可进记忆模式（自动读音）或点单词卡上的「重听」。
- **回归测试**：新增 `game-mode.test.js` 第 31 条「朗读开关：切换时只静默解锁，不朗读任何单词」，
  断言「打开朗读」这一步不会念出白纸里的任何单词（解锁用的空串不算）。该用例在旧代码上**确实失败**
  （实测报错「凭空朗读了单词：word1」），可有效防回归。
- **测试**：`game-mode.test.js` 30 → **31 条**，连同 `wordbook.test.js` 8 条，共 **39 条全绿**。

## v1.4.1（2026-09-11）· 开关标识修复

- **问题**：工具栏「音效」与「朗读」两个开关都是**纯图标按钮**（喇叭 / 声波），长得像、

  3. 整钮：关闭态整体降透明度（`opacity: .55`，原有）。
- **无障碍 / 提示**：`aria-label` 沿用「关闭音效 / 开启音效 / 关闭自动朗读 / 开启自动朗读」；
  新增 `title` 悬停提示，写明按钮归属与当前状态（如「音效：已静音（点击开启）」）。
- **改动文件**：`words_paper.html`（2 处 `span.icon-label`）、`style.css`（`.icon-label` 与
  关闭态删除线）、`script.js`（`applySound` / `applySpeak` 内补 `title`）。

## 运行方式

直接用浏览器打开 `words_paper.html` 即可，无需构建、无外部依赖。

- **单词本**：首页「我的白纸」标题栏点「单词本」→ 选一本词库 → 「导入」，
  生成一张普通白纸，录入 / 记忆 / 游戏 / 统计 / 导出全部功能可用。
- **朗读**：工具栏朗读开关控制记忆模式是否自动读音；单词卡悬停出现「重听」按钮可手动重读。

## 特别说明

- **合并边界**：v1.4.0 是 v1.2.1 与 v1.3.0 的并集，两条线任一版本的功能都不缺。
  后续若任一侧继续独立修改，请以 v1.4.0 为新基线合并，避免回退。
- **词库体积**：`wordbooks.js` 约 2 MB（9 本全量）。大词库导入的单张白纸约占 1.5 MB
  `localStorage`，若配额写满请删掉部分白纸再导入（界面会明确提示）。
- **零依赖**：朗读走浏览器原生 `speechSynthesis`，刀气走 SVG，均不引外部音频/图片/接口。
